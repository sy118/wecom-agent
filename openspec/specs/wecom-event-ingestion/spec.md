# wecom-event-ingestion 规范

## 目的
定义企业微信智能机器人事件接入、事件排重、快速确认和进入会话事件处理能力，确保事件与普通用户消息分流处理。
## 需求
### 需求: 企业微信事件接入
系统必须能够接收企业微信智能机器人事件，并将事件与普通用户消息分流处理。

#### 场景: 事件不进入普通消息队列
- **当** 系统收到 `msgtype=event` 的企业微信回调
- **那么** 系统必须将其解析为事件
- **并且** 禁止将事件作为用户消息加入 Agent 对话队列

#### 场景: 未知事件类型入库
- **当** 系统收到未知 `event.eventtype`
- **那么** 系统必须记录原始事件
- **并且** 禁止因为未知事件类型导致 Bot 进程崩溃

### 需求: 事件排重
系统必须使用企业微信事件的 `msgid` 对事件进行幂等处理。

#### 场景: 首次收到事件
- **当** 系统收到从未处理过的 `msgid`
- **那么** 系统必须创建事件记录
- **并且** 将事件标记为待处理或已处理状态

#### 场景: 重复收到事件
- **当** 系统收到已经存在的 `msgid`
- **那么** 系统必须跳过重复处理
- **并且** 返回对平台安全的成功响应

### 需求: 事件快速响应
系统必须在企业微信允许的响应窗口内确认事件接收。

#### 场景: 模板卡片事件快速确认
- **当** 系统收到 `template_card_event`
- **那么** 系统必须先完成事件排重和持久化
- **并且** 必须在五秒内向企业微信返回确认响应

#### 场景: 用户反馈事件空包响应
- **当** 系统收到 `feedback_event`
- **那么** 系统必须返回空包或等效成功响应
- **并且** 禁止在该事件响应中发送新消息或更新卡片

### 需求: 进入会话事件
系统必须支持 `enter_chat` 事件，并允许后续配置欢迎回复策略。

#### 场景: 用户当天首次进入单聊
- **当** 系统收到 `enter_chat` 事件
- **那么** 系统必须记录触发用户、Bot 和事件时间
- **并且** 若当前 Bot 配置了欢迎回复，系统必须按配置回复文本或模板卡片
