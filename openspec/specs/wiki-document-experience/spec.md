# wiki-document-experience 规范

## 目的
定义 Wiki namespace 详情页的文档搜索、Markdown 预览和文档概览体验，帮助管理员确认知识库内容和定位缺失文档。
## 需求
### 需求: Wiki 文档搜索

系统必须在 namespace 详情页提供文档搜索能力，帮助管理员确认知识库中是否存在相关内容。

#### 场景: 按关键词搜索文档

- **当** 管理员在 namespace 详情页输入关键词
- **那么** 系统必须在当前 namespace 的 Markdown 文件名和正文中搜索
- **并且** 返回匹配页面、路径和摘要

#### 场景: 搜索无结果

- **当** 当前 namespace 没有匹配文档
- **那么** 页面必须展示无结果状态
- **并且** 提供上传文档或新建草稿的后续操作入口

### 需求: Markdown 文件预览

系统必须支持在 Wiki 页面点击 Markdown 文件后查看内容预览和文件元信息。

#### 场景: 预览 Markdown 文件

- **当** 管理员点击文件树中的 `.md` 文件
- **那么** 页面必须读取该文件内容
- **并且** 以 Markdown 预览形式展示
- **并且** 展示文件路径、大小和最近修改时间

#### 场景: 文件内容读取失败

- **当** 文件不存在、路径非法或 API 返回错误
- **那么** 页面必须展示错误提示
- **并且** 不得清空当前 namespace 的其他可用信息

### 需求: Namespace 文档概览

系统必须在 namespace 详情页展示文档数量和最近变更摘要。

#### 场景: 展示文档概览

- **当** 管理员进入 namespace 详情页
- **那么** 页面必须展示 Markdown 文件总数
- **并且** 展示最近同步或最近文件变更时间
- **并且** 当 namespace 为空时提示上传 Markdown 或通过 Obsidian 同步

### 需求: Wiki 文档工作区
系统必须将 namespace 文档树、搜索结果和 Markdown 预览组织为连贯的文档工作区。

#### 场景: 浏览文档工作区
- **当** 管理员进入某个 namespace 的文档工作区
- **那么** 页面必须同时提供目录树、搜索入口和文档预览区域
- **并且** 选择文件或搜索结果后必须在同一工作区展示 Markdown 内容和文件元信息

#### 场景: 文档工作区无内容
- **当** 当前 namespace 没有 Markdown 文件
- **那么** 页面必须展示空状态
- **并且** 提供上传 Markdown、新建草稿和查看配置清单的操作入口

### 需求: 文档搜索与预览联动
系统必须让搜索结果可以直接驱动文档预览。

#### 场景: 从搜索结果打开文档
- **当** 管理员点击搜索结果中的某个 Markdown 页面
- **那么** 页面必须选中该文档
- **并且** 在预览区域展示该文档内容、路径、大小和最近修改时间

#### 场景: 搜索无结果后补充知识
- **当** 搜索没有命中文档
- **那么** 页面必须提供上传文档或创建草稿的入口
- **并且** 创建草稿时必须能带入当前搜索词作为来源线索
