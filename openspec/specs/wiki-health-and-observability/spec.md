# wiki-health-and-observability 规范

## 目的
待定 - 由归档变更 improve-wiki-knowledge-workflow 创建。归档后请更新目的。
## 需求
### 需求: Wiki 全局健康状态

系统必须提供 Wiki 全局健康状态，用于判断知识库基础设施是否可用。

#### 场景: 展示全局健康状态

- **当** 管理员访问 Wiki 总览页
- **那么** 页面必须展示 `WIKI_ROOT` 配置状态、目录存在状态、Git 仓库状态、Git remote 状态和 wiki-mcp 服务状态
- **并且** 每个健康项必须独立展示正常、警告、错误或未知

#### 场景: 部分健康检查失败

- **当** 某个健康检查失败或超时
- **那么** 页面必须展示该项失败原因
- **并且** 不得阻塞其他健康项展示

### 需求: Namespace 健康状态

系统必须在 namespace 详情页展示该知识库的可用性状态。

#### 场景: 展示 namespace 健康状态

- **当** 管理员进入 namespace 详情页
- **那么** 页面必须展示文件数量、最近同步时间、绑定 Context 数量和最近检索测试状态

#### 场景: Namespace 未绑定任何 Context

- **当** namespace 没有绑定任何 Context
- **那么** 页面必须展示未绑定提示
- **并且** 提供绑定到 Bot/Context 的操作入口

### 需求: 检索可用性测试

系统必须提供针对 namespace 的检索可用性测试。

#### 场景: 执行测试检索

- **当** 管理员输入问题并发起测试
- **那么** 系统必须调用 Wiki 搜索能力
- **并且** 展示命中数量、页面路径和摘要
- **并且** 记录最近一次测试时间和结果状态
