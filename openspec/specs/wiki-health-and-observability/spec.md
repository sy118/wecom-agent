# wiki-health-and-observability 规范

## 目的
定义 Wiki 全局和 namespace 级健康状态、端到端配置体检、运营看板和使用指标，帮助管理员判断知识库基础设施、检索链路和运营维护状态。
## 需求
### 需求: Wiki 全局健康状态

系统必须提供 Wiki 全局健康状态，用于判断知识库基础设施和 Bot 使用链路是否可用。

#### 场景: 展示全局健康状态

- **当** 管理员访问 Wiki 总览页
- **那么** 页面必须展示 `WIKI_ROOT` 配置状态、目录存在状态、Git 仓库状态、Git remote 状态、wiki-mcp 服务状态、启用的 wiki-mcp MCP Server 状态、Wiki Context 绑定状态和关联 Bot 运行状态
- **并且** 每个健康项必须独立展示正常、警告、错误或未知

#### 场景: 部分健康检查失败

- **当** 某个健康检查失败或超时
- **那么** 页面必须展示该项失败原因
- **并且** 不得阻塞其他健康项展示

#### 场景: 配置变更需要重启 Bot

- **当** MCP Server URL、启用状态、Context Wiki 绑定或检索策略发生变更
- **那么** 页面必须提示管理员关联 Bot 需要重启后才会重新加载 MCP 工具

### 需求: Namespace 健康状态

系统必须在 namespace 详情页展示该知识库的可用性状态和最近检索表现。

#### 场景: 展示 namespace 健康状态

- **当** 管理员进入 namespace 详情页
- **那么** 页面必须展示文件数量、最近同步时间、绑定 Context 数量、最近检索测试状态、待审核草稿数量和最近无命中数量

#### 场景: Namespace 未绑定任何 Context

- **当** namespace 没有绑定任何 Context
- **那么** 页面必须展示未绑定提示
- **并且** 提供绑定到 Bot/Context 的操作入口

### 需求: 检索可用性测试

系统必须提供针对 namespace 的检索可用性测试，并展示可解释的调试信息。

#### 场景: 执行测试检索

- **当** 管理员输入问题并发起测试
- **那么** 系统必须调用 Wiki 搜索能力
- **并且** 展示命中数量、页面路径、摘要、耗时和无命中提示
- **并且** 记录最近一次测试时间和结果状态

#### 场景: 测试无命中

- **当** 测试检索没有命中文档
- **那么** 页面必须提供上传文档、创建草稿或检查检索策略的操作入口

### 需求: Wiki 配置体检
系统必须提供端到端 Wiki 配置体检，用于判断 Bot 是否能够实际使用 Wiki。

#### 场景: 展示配置链路
- **当** 管理员访问 Wiki 总览页
- **那么** 页面必须展示 `WIKI_ROOT`、Git、wiki-mcp、MCP Server、Namespace、Context 绑定、Bot 运行状态和最近检索测试状态
- **并且** 每个步骤必须展示正常、警告、错误或未知状态

#### 场景: 提供修复入口
- **当** 配置体检发现某个步骤异常
- **那么** 页面必须展示异常原因
- **并且** 对可操作异常提供修复入口，例如创建 Namespace、启用 MCP Server、绑定 Context、启动或重启 Bot、执行测试检索

#### 场景: 体检失败不阻塞页面
- **当** 某个体检项检查失败或超时
- **那么** 系统必须展示该项失败原因
- **并且** 不得阻塞其他体检项展示

### 需求: Namespace 运营看板
系统必须为每个 Wiki namespace 提供运营看板，用于展示知识库使用和维护状态。

#### 场景: 展示核心运营指标
- **当** 管理员进入 namespace 的运营看板
- **那么** 页面必须展示文档数量、绑定 Context 数量、待审核草稿数量、最近更新时间、近 7 天检索次数和近 7 天无命中次数

#### 场景: 展示热门命中文档
- **当** namespace 存在检索日志
- **那么** 页面必须展示近 7 天被命中的热门文档路径和命中次数

#### 场景: 空数据展示
- **当** namespace 尚无检索日志或草稿数据
- **那么** 页面必须展示空状态
- **并且** 提供测试检索、上传文档或创建草稿的操作入口

### 需求: 无命中转草稿
系统必须允许管理员从无命中问题创建知识草稿，形成知识补充闭环。

#### 场景: 从无命中问题创建草稿
- **当** 管理员在无命中问题列表中点击创建草稿
- **那么** 系统必须打开草稿创建表单
- **并且** 自动带入 sourceType、sourceRef 和原始 query

#### 场景: 草稿创建后刷新运营指标
- **当** 管理员从无命中问题成功创建草稿
- **那么** 系统必须刷新待审核草稿数量
- **并且** 不得删除原始检索日志

### 需求: 运营指标 API
系统必须提供 namespace 级运营指标 API，供 Web 控制台展示。

#### 场景: 查询运营指标
- **当** Web 控制台请求某个 namespace 的运营指标
- **那么** API 必须返回文档数量、绑定数量、待审核草稿数量、检索次数、无命中次数、热门命中文档和热门无命中问题

#### 场景: 限制统计窗口
- **当** 请求运营指标时未提供时间范围
- **那么** 系统必须默认统计最近 7 天的数据
