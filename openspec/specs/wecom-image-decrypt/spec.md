# WeCom Image Decrypt

## 目的

定义企业微信图片消息携带 `aeskey` 时的下载、解密、多模态传递和降级行为，确保视觉模型能接收可用图片内容，同时在关闭视觉能力或解密失败时保持消息处理不中断。

## 需求

### 需求:WeComAdapter 必须支持企业微信加密图片解密
当企业微信图片消息携带 `aeskey` 时，WeComAdapter 必须下载图片密文并使用 AES 解密后再传递给 LLM；当 visionEnabled 为 false 时必须降级为文本占位。

#### 场景:图片消息包含 aeskey 且 visionEnabled 开启
- **当** WeComAdapter 解析图片消息，消息体包含图片 URL 和 `aeskey`
- **那么** 系统必须下载图片数据，使用 `aeskey` 解密，并将解密后的图片以 LLM 可消费的多模态格式传递

#### 场景:图片消息不包含 aeskey 且 visionEnabled 开启
- **当** WeComAdapter 解析图片消息，消息体包含图片 URL 但不包含 `aeskey`
- **那么** 系统必须保持现有图片处理行为，不执行解密

#### 场景:visionEnabled 关闭
- **当** WeComAdapter 解析图片消息且 Bot 未开启视觉能力
- **那么** 系统必须降级为 `[图片]` 文本占位，禁止下载或解密图片内容

#### 场景:图片下载或解密失败
- **当** 图片下载失败、AES 解密失败或解密结果无效
- **那么** 系统必须记录错误日志并降级为 `[图片解密失败]` 文本占位，禁止阻断整条消息处理

#### 场景:引用图片包含 aeskey
- **当** `body.quote` 中包含图片引用且携带 `aeskey`
- **那么** 系统必须复用相同的图片解密逻辑处理引用图片
