# wiki-retrieval-policy 规范

## 目的
定义 Wiki MCP 的检索策略、策略测试、自动检索日志、无命中汇总和回复追踪关联能力。
## 需求
### 需求: Wiki 检索策略配置

系统必须为 Wiki MCP 绑定提供面向知识库场景的检索策略配置，而不是只暴露通用强制调用开关。

#### 场景: 手动工具调用策略

- **当** 管理员选择 `manual` 策略
- **那么** 系统必须只向系统提示注入 Wiki namespace 信息
- **并且** 由模型自行决定是否调用 `wiki_read`、`wiki_search` 或其他 Wiki 工具
- **并且** 系统不得自动创建 Wiki 检索日志

#### 场景: 按问题自动搜索策略

- **当** 管理员选择 `autoSearch` 策略
- **那么** 每次用户消息处理前，系统必须使用用户问题调用 `wiki_search`
- **并且** 将命中的页面路径和摘要注入本次系统提示
- **并且** 搜索必须限定在当前绑定 namespace 范围内，除非管理员显式开启跨 namespace 搜索
- **并且** 系统必须记录本次自动搜索的检索日志

#### 场景: 固定页面注入策略

- **当** 管理员选择 `fixedPage` 策略并配置页面路径
- **那么** 每次用户消息处理前，系统必须调用 `wiki_read` 读取该页面
- **并且** 将页面内容注入本次系统提示
- **并且** 必须支持最大字符数限制，避免过长页面撑大上下文
- **并且** 系统必须记录本次固定页面读取日志

#### 场景: Wiki MCP 不可用

- **当** Context 配置了 Wiki 检索策略但 wiki-mcp 工具不可用
- **那么** Bot 不得崩溃
- **并且** 必须继续使用原始系统提示处理消息
- **并且** 必须记录错误日志供管理员排查

### 需求: 检索策略测试

系统必须允许管理员在保存前测试 Wiki 检索策略，并展示接近 Bot 实际运行时的调试反馈。

#### 场景: 测试 autoSearch

- **当** 管理员输入测试问题并点击测试
- **那么** 系统必须按当前 namespace 和策略执行检索
- **并且** 展示将注入给模型的检索摘要预览
- **并且** 展示命中文档路径、命中片段、命中数量和耗时

#### 场景: 测试 fixedPage

- **当** 管理员配置固定页面并点击测试
- **那么** 系统必须读取该页面
- **并且** 展示读取结果的截断预览
- **并且** 当页面不存在时展示明确错误和修复建议

#### 场景: 保存前发现无命中

- **当** 管理员测试 `autoSearch` 策略且没有命中文档
- **那么** 页面必须允许管理员继续保存
- **并且** 必须提示该策略可能无法提升 Bot 回答质量
- **并且** 必须提供创建草稿、上传文档或调整 query 的入口

### 需求: 检索日志关联回复追踪
系统必须支持将 Wiki 检索日志关联到具体机器人回复。

#### 场景: 记录自动搜索关联
- **当** Bot 为某次用户问题执行 `autoSearch`
- **那么** 系统必须记录检索日志
- **并且** 检索日志必须包含当前回复追踪记录 ID

#### 场景: 记录固定页面读取关联
- **当** Bot 为某次用户问题执行 `fixedPage`
- **那么** 系统必须记录读取日志
- **并且** 读取日志必须包含当前回复追踪记录 ID

#### 场景: 反馈复盘查询检索证据
- **当** 管理员查看某条反馈的关联回复
- **那么** 系统必须能够查询该回复关联的 Wiki 检索日志
- **并且** 展示 query、策略、命中文档、命中数量、耗时和错误

### 需求: Wiki 检索日志
系统必须记录 Bot 自动执行的 Wiki 检索行为，用于追踪检索效果和排查无命中问题。

#### 场景: 记录自动搜索日志
- **当** Bot Context 使用 `autoSearch` 策略处理用户消息
- **那么** 系统必须记录本次检索的 bot、context、chatKey、namespace、策略、query、命中数量、命中文档路径、耗时和错误信息
- **并且** 记录失败不得阻塞 Bot 正常回复流程

#### 场景: 记录固定页面读取日志
- **当** Bot Context 使用 `fixedPage` 策略读取 Wiki 页面
- **那么** 系统必须记录本次读取的 bot、context、chatKey、namespace、策略、页面路径、是否成功、耗时和错误信息
- **并且** 页面不存在或读取失败时必须记录错误摘要

#### 场景: 手动策略不产生自动检索日志
- **当** Bot Context 使用 `manual` 策略且系统没有自动调用 Wiki 工具
- **那么** 系统不得创建自动检索日志

### 需求: 检索日志查询
系统必须提供按 namespace 查询 Wiki 检索日志的能力。

#### 场景: 查询 namespace 检索日志
- **当** 管理员查看某个 namespace 的检索日志
- **那么** 系统必须返回该 namespace 最近的检索记录
- **并且** 每条记录必须包含 query、策略、命中数量、命中文档路径、耗时、错误和创建时间

#### 场景: 按时间和命中状态筛选
- **当** 管理员按时间范围或无命中状态筛选检索日志
- **那么** 系统必须只返回符合条件的记录

### 需求: 无命中问题汇总
系统必须能够汇总 Wiki 检索无命中的问题，用于知识补充。

#### 场景: 查看无命中问题
- **当** 管理员查看某个 namespace 的无命中问题
- **那么** 系统必须展示最近无命中的 query、出现次数、最近出现时间和关联 context 信息

#### 场景: 无命中问题去重
- **当** 多条检索日志具有相同 namespace 和 query 且命中数量为 0
- **那么** 系统必须在无命中汇总中合并计数
