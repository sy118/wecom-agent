# wiki-retrieval-policy 规范

## 目的
待定 - 由归档变更 improve-wiki-knowledge-workflow 创建。归档后请更新目的。
## 需求
### 需求: Wiki 检索策略配置

系统必须为 Wiki MCP 绑定提供面向知识库场景的检索策略配置，而不是只暴露通用强制调用开关。

#### 场景: 手动工具调用策略

- **当** 管理员选择 `manual` 策略
- **那么** 系统必须只向系统提示注入 Wiki namespace 信息
- **并且** 由模型自行决定是否调用 `wiki_read`、`wiki_search` 或其他 Wiki 工具

#### 场景: 按问题自动搜索策略

- **当** 管理员选择 `autoSearch` 策略
- **那么** 每次用户消息处理前，系统必须使用用户问题调用 `wiki_search`
- **并且** 将命中的页面路径和摘要注入本次系统提示
- **并且** 搜索必须限定在当前绑定 namespace 范围内，除非管理员显式开启跨 namespace 搜索

#### 场景: 固定页面注入策略

- **当** 管理员选择 `fixedPage` 策略并配置页面路径
- **那么** 每次用户消息处理前，系统必须调用 `wiki_read` 读取该页面
- **并且** 将页面内容注入本次系统提示
- **并且** 必须支持最大字符数限制，避免过长页面撑大上下文

#### 场景: Wiki MCP 不可用

- **当** Context 配置了 Wiki 检索策略但 wiki-mcp 工具不可用
- **那么** Bot 不得崩溃
- **并且** 必须继续使用原始系统提示处理消息
- **并且** 必须记录错误日志供管理员排查

### 需求: 检索策略测试

系统必须允许管理员在保存前测试 Wiki 检索策略。

#### 场景: 测试 autoSearch

- **当** 管理员输入测试问题并点击测试
- **那么** 系统必须按当前 namespace 和策略执行检索
- **并且** 展示将注入给模型的检索摘要预览

#### 场景: 测试 fixedPage

- **当** 管理员配置固定页面并点击测试
- **那么** 系统必须读取该页面
- **并且** 展示读取结果的截断预览
