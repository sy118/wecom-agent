# 管理控制台 (Admin Console)

## 目的

提供基于 JWT 认证的 Web 管理界面，支持机器人管理、上下文配置、绑定管理、会话监控和全局功能导航的完整操作能力。

## 需求

### 需求:管理员身份认证
系统必须对管理控制台的所有 API 请求进行 JWT 认证，防止未授权访问。

#### 场景:登录获取 Token
- **当** 管理员 POST /api/auth/login 提交正确的 ADMIN_PASSWORD
- **那么** 系统返回有效期 24 小时的 JWT token

#### 场景:错误密码拒绝登录
- **当** 管理员提交错误的密码
- **那么** 系统返回 401，不返回 token

#### 场景:未携带 Token 的请求被拒绝
- **当** 请求未携带 Authorization: Bearer <token> 头
- **那么** 系统返回 401，拒绝处理

#### 场景:Token 过期后需重新登录
- **当** 请求携带已过期的 JWT token
- **那么** 系统返回 401，前端跳转到登录页

### 需求:全局导航布局
管理控制台左侧边栏必须提供全局顶级导航项，并根据当前 URL 路径自动高亮对应菜单。

#### 场景:用户看到完整的侧边栏导航
- **当** 用户登录后进入任意页面
- **那么** 左侧边栏必须显示机器人管理、MCP 服务器、Skills、定时任务和会话监控等全局入口
- **并且** 会话监控必须与上方功能区用视觉分隔线区分

#### 场景:点击全局导航项
- **当** 用户点击 MCP 服务器、Skills 或定时任务导航项
- **那么** 页面必须分别跳转到 `/mcp-servers`、`/skills` 或 `/scheduled-tasks`
- **并且** 当前菜单项必须高亮选中

### 需求:机器人管理界面
管理控制台必须提供机器人的完整 CRUD 操作界面和实时状态显示。

#### 场景:机器人列表展示
- **当** 管理员访问机器人管理页
- **那么** 界面必须展示所有机器人的名称、状态（运行中/已停止/错误）、今日消息数

#### 场景:实时状态更新
- **当** 机器人状态发生变化（启动/停止/错误）
- **那么** 管理台必须通过 SSE 连接实时更新状态显示，无需手动刷新

#### 场景:启动停止操作
- **当** 管理员点击启动或停止按钮
- **那么** 界面必须显示操作进行中状态，操作完成后更新显示结果

### 需求:上下文配置界面
管理控制台必须提供上下文的创建和编辑界面，包含系统提示词编辑器。

#### 场景:系统提示词编辑
- **当** 管理员编辑上下文的系统提示词
- **那么** 界面必须提供多行文本编辑器，支持输入 Markdown 格式的提示词

#### 场景:可查项目多选
- **当** 管理员配置上下文的 allowed_projects
- **那么** 界面必须提供多选组件，允许从预定义项目列表中勾选（至少一个必选）

#### 场景:设置默认上下文
- **当** 管理员将某上下文设为默认
- **那么** 界面必须清晰标识当前默认上下文，同一机器人下只能有一个默认

### 需求:绑定管理界面
管理控制台必须提供 chatKey 与上下文绑定关系的管理界面。

#### 场景:创建绑定
- **当** 管理员填写 chatKey（群ID或用户ID）、显示名称，并选择目标上下文
- **那么** 系统创建绑定关系，界面刷新显示新绑定

#### 场景:绑定列表展示
- **当** 管理员查看绑定管理页
- **那么** 界面必须展示所有绑定关系：显示名称、chatKey、绑定的上下文名称

### 需求:会话监控界面
管理控制台必须提供当前活跃会话的查看和管理功能。

#### 场景:活跃会话列表
- **当** 管理员访问会话监控页
- **那么** 界面必须展示所有活跃会话：chatKey、绑定上下文名、消息数、最后活跃时间、剩余 TTL

#### 场景:查看对话历史
- **当** 管理员点击某个会话
- **那么** 界面必须展示该会话的完整对话历史（HumanMessage 和 AIMessage 交替显示）

#### 场景:手动清除会话
- **当** 管理员点击清除某个会话
- **那么** 系统立即删除该会话，界面从列表中移除该条目

### 需求:Skill 管理页面

管理控制台必须在左侧导航提供全局 Skill 管理页面，支持上传文件夹、查看资源索引、预览 `SKILL.md`、启用、禁用、删除和查看审计。

#### 场景:进入 Skill 管理

- **当** 管理员点击左侧导航的 Skills
- **那么** 页面必须跳转到全局 Skill 管理页面
- **并且** 展示全局已安装的 Skill 列表

#### 场景:上传 Skill 文件夹

- **当** 管理员选择一个本地 Skill 文件夹并提交
- **那么** 前端必须以 multipart 形式上传该文件夹中的文件
- **并且** 上传成功后刷新列表显示新 Skill

#### 场景:展示 Skill 资源

- **当** Skill 已安装
- **那么** 页面必须展示 Skill 名称、描述、启用状态、bundle hash、脚本数量、reference 数量和 asset 数量

#### 场景:预览 SKILL.md

- **当** 管理员点击预览
- **那么** 页面必须展示该 Skill 的 `SKILL.md` 内容

#### 场景:启停 Skill

- **当** 管理员切换 Skill 启用状态
- **那么** 系统必须保存修改
- **并且** 正在运行的 Bot 需要重启后生效的提示必须可见

### 需求:Context Skill 配置区

Context 创建和编辑表单必须提供 Skill 能力配置区，动态展示全局已安装的 Skill，并支持配置启用状态、参数和 `forceUse`。

#### 场景:展示可用 Skill

- **当** 管理员打开 Context 表单
- **那么** 页面必须加载全局 Skill 列表
- **并且** 为每个 Skill 展示开关、名称、描述和 `forceUse` 配置

#### 场景:配置 Skill 参数

- **当** 管理员为启用的 Skill 填写参数
- **那么** 页面必须将结果保存到 `skillConfigs.params`

#### 场景:没有 Skill 时提示

- **当** 全局未安装任何 Skill
- **那么** Context Skill 配置区必须提示管理员先到左侧 Skill 管理页上传 Skill 文件夹

### 需求:Skill 审计查看

管理控制台必须提供 Skill 脚本执行审计记录查看能力。

#### 场景:查看审计列表

- **当** 管理员打开某个 Skill 的审计记录
- **那么** 页面必须展示执行时间、状态、耗时、Context、chatKey、输入摘要、输出摘要和错误摘要

#### 场景:审计脱敏显示

- **当** 审计记录包含敏感参数
- **那么** 页面必须显示脱敏值，禁止展示明文密钥

### 需求:移除 manifest 表单

管理控制台必须移除 prompt/script 类型选择、脚本入口文件手填和 manifest JSON 表单作为创建 Skill 的主路径；创建 Skill 时禁止依赖手写 manifest。

#### 场景:创建 Skill

- **当** 管理员需要新增 Skill
- **那么** 页面必须引导上传包含 `SKILL.md` 的文件夹
- **并且** 不要求管理员手填 `manifest.script.entry`
