## 新增需求

### 需求: Namespace 运营看板
系统必须为每个 Wiki namespace 提供运营看板，用于展示知识库使用和维护状态。

#### 场景: 展示核心运营指标
- **当** 管理员进入 namespace 的运营看板
- **那么** 页面必须展示文档数量、绑定 Context 数量、待审核草稿数量、最近更新时间、近 7 天检索次数和近 7 天无命中次数

#### 场景: 展示热门命中文档
- **当** namespace 存在检索日志
- **那么** 页面必须展示近 7 天被命中的热门文档路径和命中次数

#### 场景: 空数据展示
- **当** namespace 尚无检索日志或草稿数据
- **那么** 页面必须展示空状态
- **并且** 提供测试检索、上传文档或创建草稿的操作入口

### 需求: 无命中转草稿
系统必须允许管理员从无命中问题创建知识草稿，形成知识补充闭环。

#### 场景: 从无命中问题创建草稿
- **当** 管理员在无命中问题列表中点击创建草稿
- **那么** 系统必须打开草稿创建表单
- **并且** 自动带入 sourceType、sourceRef 和原始 query

#### 场景: 草稿创建后刷新运营指标
- **当** 管理员从无命中问题成功创建草稿
- **那么** 系统必须刷新待审核草稿数量
- **并且** 不得删除原始检索日志

### 需求: 运营指标 API
系统必须提供 namespace 级运营指标 API，供 Web 控制台展示。

#### 场景: 查询运营指标
- **当** Web 控制台请求某个 namespace 的运营指标
- **那么** API 必须返回文档数量、绑定数量、待审核草稿数量、检索次数、无命中次数、热门命中文档和热门无命中问题

#### 场景: 限制统计窗口
- **当** 请求运营指标时未提供时间范围
- **那么** 系统必须默认统计最近 7 天的数据
