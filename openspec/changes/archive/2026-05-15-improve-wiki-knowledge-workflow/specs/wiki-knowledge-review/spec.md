## 新增需求

### 需求: Wiki 知识草稿

系统必须支持将自动提炼的知识先保存为草稿，而不是默认直接写入正式 Wiki 页面。

#### 场景: 创建知识草稿

- **当** Bot、Skill 或定时任务提炼出候选知识
- **那么** 系统必须允许将候选知识保存为草稿
- **并且** 草稿必须包含 namespace、建议页面路径、Markdown 内容、来源类型、来源引用和状态

#### 场景: 查看待审核草稿

- **当** 管理员进入 namespace 的知识草稿区域
- **那么** 页面必须展示待审核草稿列表
- **并且** 支持查看 Markdown 内容预览和来源信息

### 需求: 草稿审核

系统必须支持管理员批准或拒绝知识草稿。

#### 场景: 批准草稿

- **当** 管理员批准某条草稿
- **那么** 系统必须将草稿内容写入或追加到目标 Markdown 页面
- **并且** 执行 Git commit
- **并且** 将草稿状态更新为已合并

#### 场景: 拒绝草稿

- **当** 管理员拒绝某条草稿并填写原因
- **那么** 系统必须将草稿状态更新为已拒绝
- **并且** 保存拒绝原因
- **并且** 不得修改正式 Wiki 文件

#### 场景: 审核操作失败

- **当** 写入文件、Git commit 或状态更新失败
- **那么** 系统必须返回明确错误
- **并且** 不得将草稿错误标记为已合并

### 需求: wiki-compiler 默认进入草稿流程

系统必须将 wiki-compiler 的推荐使用方式调整为生成知识草稿。

#### 场景: wiki-compiler 提炼新知识

- **当** wiki-compiler 判断对话中存在可沉淀知识
- **那么** 推荐流程必须创建 Wiki 知识草稿
- **并且** 由管理员审核后再写入正式 Wiki
