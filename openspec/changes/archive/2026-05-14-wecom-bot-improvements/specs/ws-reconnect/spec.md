## 新增需求

### 需求:disconnected_event 处理
系统必须监听企微推送的 `disconnected_event` 事件，并在收到后执行重连逻辑。

#### 场景:收到 disconnected_event 后触发重连
- **当** 企微通过长连接推送 `disconnected_event`（表示有新连接建立，旧连接被踢掉）
- **那么** 系统必须记录断线原因，等待一段随机 jitter 后发起重连，不得立即重连（避免与新连接冲突）

#### 场景:网络异常触发重连
- **当** WebSocket 连接因网络错误断开（`error` 事件或连接关闭）
- **那么** 系统必须立即开始重连流程，使用指数退避策略

### 需求:指数退避重连策略
系统必须使用指数退避策略进行重连，避免在服务端压力大时造成重连风暴。

#### 场景:首次重连
- **当** 连接断开后第一次尝试重连
- **那么** 系统必须等待 1 秒后发起重连

#### 场景:重连失败后继续退避
- **当** 重连尝试失败
- **那么** 系统必须将等待时间翻倍（1s → 2s → 4s → 8s → ...），最大等待时间不超过 60 秒，并加入随机 jitter（±20%）

#### 场景:重连成功后重置退避
- **当** 重连成功并完成 `aibot_subscribe` 订阅
- **那么** 系统必须将退避计时器重置为初始值（1 秒）

#### 场景:Bot 主动停止时不重连
- **当** `BotInstance.stop()` 被调用（管理员主动停止机器人）
- **那么** 系统禁止发起重连，必须彻底断开连接

### 需求:重连期间的消息队列保护
系统必须在连接断开期间保护消息队列，避免重连期间的消息丢失或错误。

#### 场景:重连期间收到新消息
- **当** 连接正在重连过程中，有新消息进入队列
- **那么** 系统必须拒绝处理新消息（返回背压响应），直到重连成功
