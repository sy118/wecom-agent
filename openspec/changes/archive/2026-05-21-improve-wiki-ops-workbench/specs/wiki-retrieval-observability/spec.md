## 新增需求

### 需求: Wiki 检索日志
系统必须记录 Bot 自动执行的 Wiki 检索行为，用于追踪检索效果和排查无命中问题。

#### 场景: 记录自动搜索日志
- **当** Bot Context 使用 `autoSearch` 策略处理用户消息
- **那么** 系统必须记录本次检索的 bot、context、chatKey、namespace、策略、query、命中数量、命中文档路径、耗时和错误信息
- **并且** 记录失败不得阻塞 Bot 正常回复流程

#### 场景: 记录固定页面读取日志
- **当** Bot Context 使用 `fixedPage` 策略读取 Wiki 页面
- **那么** 系统必须记录本次读取的 bot、context、chatKey、namespace、策略、页面路径、是否成功、耗时和错误信息
- **并且** 页面不存在或读取失败时必须记录错误摘要

#### 场景: 手动策略不产生自动检索日志
- **当** Bot Context 使用 `manual` 策略且系统没有自动调用 Wiki 工具
- **那么** 系统不得创建自动检索日志

### 需求: 检索日志查询
系统必须提供按 namespace 查询 Wiki 检索日志的能力。

#### 场景: 查询 namespace 检索日志
- **当** 管理员查看某个 namespace 的检索日志
- **那么** 系统必须返回该 namespace 最近的检索记录
- **并且** 每条记录必须包含 query、策略、命中数量、命中文档路径、耗时、错误和创建时间

#### 场景: 按时间和命中状态筛选
- **当** 管理员按时间范围或无命中状态筛选检索日志
- **那么** 系统必须只返回符合条件的记录

### 需求: 无命中问题汇总
系统必须能够汇总 Wiki 检索无命中的问题，用于知识补充。

#### 场景: 查看无命中问题
- **当** 管理员查看某个 namespace 的无命中问题
- **那么** 系统必须展示最近无命中的 query、出现次数、最近出现时间和关联 context 信息

#### 场景: 无命中问题去重
- **当** 多条检索日志具有相同 namespace 和 query 且命中数量为 0
- **那么** 系统必须在无命中汇总中合并计数
