## 上下文

普通会话绑定当前由绑定管理页和 `/api/bots/:botId/bindings` 系列接口管理，已支持列表、新增和删除。底层绑定唯一性由 `botId + chatKey` 保证，消息路由依赖 `chatKey` 查找对应上下文。由于没有显式编辑能力，管理员调整绑定名称、类型或上下文时需要删除再新建，容易造成操作中断和运行态不一致。

会话 TTL 当前以 `contexts.session_ttl_min` 作为实际生效配置，创建或续期 session 时写入 `expiresAt = now + sessionTtlMin`。会话监控页展示的“剩余 TTL”是根据后端返回的 `expiresAt` 在前端计算。现有数据库默认值为 30 分钟，但缺少平台级默认配置入口来影响新建上下文的初始值。

## 目标 / 非目标

**目标：**

- 为普通会话绑定提供显式编辑能力。
- 保持 `chatKey` 不可编辑，避免绑定身份变化和唯一性冲突。
- 绑定编辑成功后同步运行中 Bot 的内存绑定状态。
- 增加平台默认会话 TTL 配置，作为新建上下文的默认 `sessionTtlMin`。
- 保持已有上下文、存量 session、滑动续期和清理机制不变。

**非目标：**

- 不支持编辑绑定时修改 `chatKey`。
- 不把平台默认 TTL 作为强制全局 TTL 覆盖上下文配置。
- 不批量重算已有 session 的 `expiresAt`。
- 不改变会话监控页“剩余 TTL”的计算语义。
- 不调整 wiki 绑定能力；本变更仅覆盖普通 chatKey 路由绑定。

## 决策

### 绑定编辑按 `botId + bindingId` 定位

编辑接口使用绑定记录 ID 和 botId 定位目标记录，只允许更新 `chatName`、`chatType`、`contextId`。请求体中的 `chatKey` 如果出现也禁止作为更新字段处理。

替代方案是继续复用现有创建接口的 upsert 语义，但 upsert 以 `botId + chatKey` 定位，会让“编辑”和“覆盖创建”的行为混在一起，不利于表达 `chatKey` 不可修改的产品语义。

### 运行时同步复用稳定 `chatKey`

因为 `chatKey` 不允许修改，编辑后只需要用原 `chatKey` 覆盖运行中 Bot 的绑定映射内容。无需处理旧 key 删除和新 key 插入，也不会影响已建立 session 的 `chatKey` 身份。

### 平台默认 TTL 只作为创建上下文的默认值

实际生效的 TTL 仍存储在每个上下文的 `sessionTtlMin` 中。平台默认 TTL 用于上下文创建表单初始值，以及后端创建上下文时请求未提供 `sessionTtlMin` 的默认填充值。

替代方案是让 session 运行时直接读取平台默认 TTL，但这会和上下文级 TTL 配置冲突，也会让全局配置修改对现有业务产生不可预期影响。

### 默认 TTL 需要前后端共同兜底

前端在创建上下文时读取平台默认 TTL 填充表单，提升用户体验；后端在创建上下文时也使用平台默认 TTL 兜底，保证 API 调用者不经过前端时行为一致。

## 风险 / 权衡

- 绑定编辑与删除的运行态一致性风险 → 编辑必须在持久化成功后同步运行中 Bot 的绑定映射；如果同步失败，应返回错误或记录可观测错误，避免数据库与运行态静默分歧。
- 默认 TTL 配置优先级混淆 → 明确优先级为“请求显式 `sessionTtlMin` > 平台默认 TTL > 系统硬编码兜底”，且平台默认 TTL 不覆盖已有上下文。
- 存量 session 预期误解 → 文档和 UI 需保持“剩余 TTL 来源于 session.expiresAt”的语义；修改默认 TTL 不会立即改变已存在 session。
- 前端时间偏差 → 本变更不改变前端基于本地时间显示剩余 TTL 的现状；实际过期仍由后端 `expiresAt` 和清理逻辑决定。
