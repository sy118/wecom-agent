## 为什么

当前普通会话绑定仅支持新增和删除，管理员无法在不重建绑定的情况下调整绑定名称、类型或关联上下文；同时新建上下文的会话 TTL 仍依赖固定默认值，无法按部署或运营偏好配置默认值。

本变更将补齐绑定编辑能力，并引入平台默认会话 TTL 配置，使新建上下文的默认超时时间可配置，同时保持已有上下文和存量会话行为稳定。

## 变更内容

- 为普通会话绑定增加编辑能力。
  - 允许编辑 `chatName`、`chatType`、`contextId`。
  - 禁止编辑 `chatKey`，`chatKey` 作为绑定身份和唯一键保持稳定。
  - 编辑成功后同步更新运行中机器人的内存绑定映射。
- 增加平台默认会话 TTL 配置。
  - 仅作为新建上下文时 `sessionTtlMin` 的默认值。
  - 不覆盖已有上下文的 `sessionTtlMin`。
  - 不立即重算存量 session 的 `expiresAt`，也不改变运行中 session 的滑动过期语义。
- 不引入破坏性变更。

## 功能 (Capabilities)

### 新增功能
- `platform-default-session-ttl`: 平台可配置默认会话 TTL，用于新建上下文默认值。

### 修改功能
- `context-routing`: 普通 chatKey 路由绑定支持按绑定记录编辑元数据和关联上下文，且 `chatKey` 不可修改。
- `session-management`: 上下文会话 TTL 的默认值从平台默认 TTL 配置中取得；已有上下文和存量会话不被全局默认值覆盖。

## 影响

- 前端：绑定管理页新增编辑入口和编辑表单；上下文创建表单使用平台默认会话 TTL 作为初始值。
- 后端 API：普通绑定增加按 `botId + bindingId` 更新接口；平台配置增加默认会话 TTL 的读取入口。
- 数据/配置：需要新增或复用平台配置存储默认 TTL；保留 `contexts.session_ttl_min` 作为实际生效配置。
- 运行时：绑定编辑成功后更新运行中 Bot 的绑定映射；不修改 session 清理和续期机制。
