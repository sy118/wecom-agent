## 新增需求

### 需求: 反馈事件来源草稿
系统必须支持从用户反馈事件创建 Wiki 知识草稿。

#### 场景: 草稿记录反馈来源
- **当** 系统从用户反馈创建知识草稿
- **那么** 草稿的来源类型必须为 `feedback-event`
- **并且** 来源引用必须包含反馈处理项和回复追踪记录的可追溯标识

#### 场景: 审核反馈来源草稿
- **当** 管理员打开来源类型为 `feedback-event` 的草稿详情
- **那么** 系统必须展示原问题、原回答、用户反馈内容、负反馈原因和检索证据
- **并且** 管理员必须能够编辑草稿内容后再合并

#### 场景: 合并反馈来源草稿
- **当** 管理员批准来源类型为 `feedback-event` 的草稿
- **那么** 系统必须按现有合并策略写入 Wiki
- **并且** 将关联反馈处理项标记为已解决
