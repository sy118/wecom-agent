## 新增需求

### 需求: 回复追踪记录
系统必须为每次可反馈的机器人回复创建回复追踪记录。

#### 场景: 普通模型回复完成
- **当** Bot 生成并发送一条普通回复
- **那么** 系统必须创建或更新一条回复追踪记录
- **并且** 记录必须包含 Bot、Context、chatKey、用户问题摘要、机器人回答摘要、模型供应商和创建时间

#### 场景: 流式回复完成
- **当** Bot 以流式方式完成回复
- **那么** 系统必须将最终回复内容关联到同一条回复追踪记录
- **并且** 禁止为同一次流式回复创建多条追踪记录

### 需求: 反馈 ID 注入
系统必须为支持用户反馈的回复设置可回溯的反馈 ID。

#### 场景: 回复支持反馈控件
- **当** Bot 发送支持反馈信息的回复
- **那么** 系统必须生成唯一反馈 ID
- **并且** 企业微信后续 `feedback_event.id` 必须能够定位到对应回复追踪记录

#### 场景: 反馈 ID 未能发送
- **当** 平台发送接口不支持或拒绝反馈 ID
- **那么** 系统必须保留回复追踪记录
- **并且** 将该记录标记为不可通过企业微信反馈反查

### 需求: 检索证据关联
系统必须将一次回复使用的 Wiki 检索日志关联到对应回复追踪记录。

#### 场景: 自动搜索产生检索日志
- **当** Bot 在回复前执行 Wiki `autoSearch`
- **那么** 系统必须将本次检索日志的 `responseRunId` 设置为当前回复追踪记录

#### 场景: 固定页面读取产生检索日志
- **当** Bot 在回复前执行 Wiki `fixedPage`
- **那么** 系统必须将读取日志的 `responseRunId` 设置为当前回复追踪记录

### 需求: 反馈反查回复
系统必须能够通过企业微信反馈 ID 查询对应回复上下文。

#### 场景: 反馈 ID 已关联
- **当** 系统处理 `feedback_event.id`
- **那么** 系统必须找到对应回复追踪记录
- **并且** 返回关联的用户问题、机器人回答、Context、Session 和检索证据供后续处理

#### 场景: 反馈 ID 未关联
- **当** 系统无法通过 `feedback_event.id` 找到回复追踪记录
- **那么** 系统必须保留原始反馈事件
- **并且** 创建无法关联的反馈运营项或错误状态供管理员排查
