## 新增需求

### 需求:AgentEngine 必须稳定处理 MCP Agent 执行结果

AgentEngine 必须稳定处理带 MCP tools 的 Agent 执行过程，避免只读取最后一条空 content 导致企业微信空回复；必须提供足够日志区分模型未调用工具、工具调用失败、结果提取失败等问题。

#### 场景:Agent 返回空 content 的 tool calling 中间态

- **当** Agent 执行结果中最后一条消息 content 为空
- **且** 消息序列中存在 tool call 中间态或其他非空 AI 文本
- **那么** 系统不得直接将空字符串作为最终回复
- **并且** 必须从消息序列中提取最后一个有效非空 AI 文本，或返回明确 fallback 文案

#### 场景:执行过程中记录 MCP 工具调用状态

- **当** Agent 执行带 tools 的请求
- **那么** 系统必须记录工具调用开始、结束和错误日志
- **并且** 日志必须能帮助判断是 LLM 未发起 tool call、MCP tool 执行失败，还是最终回复提取为空

#### 场景:Agent 执行使用递归限制

- **当** AgentEngine 调用带 tools 的 Agent
- **那么** 系统必须传入可配置的 recursionLimit
- **并且** 默认值应能支持代码库检索类多步工具调用

#### 场景:递归超限时生成阶段性总结

- **当** Agent 执行触发 `GRAPH_RECURSION_LIMIT` 或 recursion limit 相关错误
- **且** 执行过程中已收集到中间消息
- **那么** 系统必须使用不带 tools 的基础模型基于中间消息生成阶段性总结
- **并且** 不得直接向用户返回内部错误信息

#### 场景:最终回复为空时使用降级文案

- **当** Agent 执行完成后仍无法提取有效文本
- **那么** 系统必须返回明确的降级提示
- **并且** 禁止向企业微信发送空内容
