## 新增需求

### 需求: 行动化健康总览
系统必须将 Wiki 健康状态转换为可操作的配置清单和修复入口。

#### 场景: 展示配置清单
- **当** 管理员进入 Wiki 页面
- **那么** 页面必须展示 WIKI_ROOT、Git、wiki-mcp、MCP Server、Namespace、Context 绑定、Bot 运行状态和检索测试的状态清单
- **并且** 每个异常或警告项必须展示原因和修复入口

#### 场景: 配置异常进入待办
- **当** 配置清单中存在错误或警告项
- **那么** 系统必须在统一待办中展示对应配置待办
- **并且** 待办项必须指向可执行的修复动作

### 需求: 运营指标可下钻
系统必须让运营指标成为处理入口，而不仅是静态统计。

#### 场景: 从指标进入问题列表
- **当** 管理员点击待审核草稿、无命中、负反馈或配置异常指标
- **那么** 页面必须切换到对应工作区
- **并且** 自动应用与该指标一致的筛选条件

#### 场景: 空运营指标
- **当** 当前 namespace 尚无检索日志、反馈或草稿数据
- **那么** 分析区域必须展示空状态
- **并且** 提供测试检索、上传文档或创建草稿的操作入口
