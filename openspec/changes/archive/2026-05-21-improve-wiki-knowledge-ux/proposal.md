## 为什么

当前 Wiki 知识库页面已经具备文档、检索、草稿、反馈、配置体检和运营指标等能力，但交互更像功能集合页，管理员需要在多个 Tab 和卡片之间自行拼出“今天该处理什么、为什么处理、处理后如何改善机器人回答”的闭环。

这次变更希望在不改变现有 Ant Design 管理台风格的前提下，把 Wiki 知识库升级为更清晰的知识运营工作台：先展示状态和待办，再引导用户完成文档维护、反馈处理、草稿审核和配置修复。

## 变更内容

- 重组 `/wiki` 信息架构，保持当前页面的卡片、列表、Tabs、Modal、Statistic、Alert、Tag 等视觉语言，不引入新的重型设计系统。
- 将“草稿、负反馈、无命中问题、配置异常”整合为统一待办入口，帮助管理员按优先级处理知识质量问题。
- 优化 namespace 详情页布局，让文档树、搜索、预览/编辑形成更连续的文档工作区。
- 优化反馈处理链路，在反馈详情中突出原问题、原回答、检索证据、负反馈原因和推荐处理动作。
- 优化草稿审核弹窗或详情区域，形成“来源证据 / 草稿内容 / 合并差异”的三栏审核心智。
- 将首次使用向导升级为可持续显示的配置清单，让用户随时知道 Wiki 到 Bot 的链路是否可用。
- 强化运营总览，用行动卡片表达待处理问题，而不是只展示分散指标。

## 功能 (Capabilities)

### 新增功能

- `wiki-workbench-experience`: 定义 Wiki 知识运营工作台的信息架构、统一待办、行动总览和现有页面风格约束。

### 修改功能

- `wiki-document-experience`: 将文档浏览、搜索、预览和编辑入口调整为更连贯的分栏工作区。
- `wiki-knowledge-review`: 优化反馈闭环和草稿审核体验，支持证据驱动的反馈处理与三栏审核。
- `wiki-health-and-observability`: 将健康状态和运营指标升级为面向行动的总览与待办来源。
- `wiki-onboarding-workflow`: 将一次性向导扩展为可恢复、可持续展示的配置清单。

## 影响

- 主要影响 `apps/web/src/pages/WikiPage.tsx` 的信息架构、组件组织和交互状态。
- 可能影响 `apps/web/src/api/index.ts` 的聚合请求方式，但优先复用现有 API。
- 后端 API 原则上不新增复杂数据模型；若实现时发现聚合待办性能或接口响应不足，可在 `apps/api/src/routes/wiki.ts` 增加轻量聚合接口。
- 不引入新的 UI 框架；继续使用现有 Ant Design 组件和当前页面的管理台视觉风格。
- 不改变 Wiki MCP、知识草稿、反馈入库、Git 合并等已有业务语义。
