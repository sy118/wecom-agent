## 上下文

当前 wecom-agent 前端将 MCP 服务器、Skills、定时任务作为每个 Bot 的子页面（路由 `/bots/:botId/mcp-servers` 等），通过 Bot 列表表格行内的操作按钮进入。然而后端数据模型中这三者是全局资源，与 Bot 通过上下文（Context）建立多对多关联。UI 与数据模型的错位需要通过导航重构来修正。

项目使用 React + React Router v6 + Ant Design 5.x，后端为 Node.js API。

## 目标 / 非目标

**目标：**
- 将 MCP 服务器、Skills、定时任务提升为左侧边栏顶级导航项
- 路由去除 botId 前缀，改为全局路径
- Bot 表格行内操作按钮从 6 个缩减为 3 个
- 定时任务支持选择目标机器人
- 上下文配置页面的 MCP/Skill 绑定区域改为从全局池选择

**非目标：**
- 后端 API 路由重构（前端直接调用全局 API，后端路由已支持全局查询则无需改动）
- 权限系统或多租户支持
- MCP/Skill 的分组、标签、搜索功能（留待后续迭代）

## 决策

### 决策 1：侧边栏菜单结构

采用单层顶级菜单，不使用折叠子菜单：

```
机器人管理
MCP 服务器
Skills
定时任务
──────────
会话监控
```

**理由**：Bot 数量可能增多，但顶级功能区数量固定（5个），单层菜单最简洁。会话监控与配置类功能性质不同，用分隔线区分。

**备选方案**：将 MCP/Skills/定时任务放在"配置"折叠组下 → 增加一次点击，不值得。

### 决策 2：路由结构

```
旧路由                              新路由
/bots/:botId/mcp-servers    →      /mcp-servers
/bots/:botId/skills         →      /skills
/bots/:botId/scheduled-tasks →     /scheduled-tasks
```

旧路由不保留重定向，直接废弃。这些页面不是外部链接入口，无需向后兼容。

### 决策 3：定时任务的目标机器人字段

在新建/编辑定时任务的表单中新增"目标机器人"下拉选择，选项来自 `/api/bots` 列表，支持"全部机器人"选项（值为 `null` 或空）。

列表视图新增"目标机器人"列，显示 Bot 名称或"全部"。

### 决策 4：上下文配置中的 MCP/Skill 绑定

上下文配置 Modal 中的 MCP 能力区域和 Skill 区域保持现有 UI 结构（开关 + 参数），但数据来源从"该 Bot 的 MCP 列表"改为"全局 MCP 列表"。这是纯数据源变更，UI 改动最小。

### 决策 5：后端 API 评估

需确认后端是否已有全局 MCP/Skill/定时任务的 API（不带 botId 前缀）。若已有，前端直接切换调用路径；若无，需后端新增全局查询接口。

## 风险 / 权衡

- **破坏性路由变更** → 用户书签或分享的链接会失效。缓解：这是内部管理工具，影响可控。
- **上下文页面数据源变更** → 若后端 MCP/Skill 列表 API 不支持全局查询，需后端配合。缓解：提前确认 API 现状。
- **定时任务目标机器人字段** → 现有定时任务数据中若无 botId 字段，需数据迁移或默认值处理。缓解：默认为"全部"，不影响现有任务行为。

## 迁移计划

1. 前端路由和页面改造（纯前端，可独立部署）
2. 确认后端全局 API 可用性，必要时新增接口
3. 定时任务表结构若需新增 botId 字段，执行数据库迁移（默认 null = 全部）
